# VDF 6.0 Source→Block Mapping Audit

## 목적

이 감사의 목적은 VDF 6.0의 규칙을 고치는 것이 아니라, 현재 6.0이 강의노트의 어떤 원문 구조를 어떤 블록으로 변환하는지 확인하는 것이다. 5.x에서 제약조건이 누적되며 과적합된 경험을 반복하지 않기 위해, 단일 케이스 실패가 아니라 **여러 독립 케이스에서 반복되는 패턴**만 수정 후보로 올린다.

- Reference Engine: VDF 6.0 Stable
- 6.1: HOLD / Experimental
- rules.json: 변경 없음
- 평가 대상: CASE-01C, CASE-02, CASE-03의 실제 6.0 실행 결과
- 원칙: Golden 맞추기보다 기존 성공 판단을 깨뜨리지 않는 일반화 성능을 우선한다.

## 전체 결론

세 케이스를 함께 보면 VDF 6.0의 Label Test → Info Type → Image Gate → Card 판단은 대체로 살아 있다. 특히 CASE-02는 이미지 후보를 적극적으로 살리면서도 애매한 항목을 shape로 남기는 VDF 6.0의 철학을 잘 보여준다. CASE-03의 0-image도 내용이 주로 정의·분류·절차이므로 현재로서는 실패로 보지 않는다.

반면 **본문 안의 `한 줄 정리`가 독립 블록으로 재생성되는 패턴은 3/3 케이스에서 반복**되었다. 이는 현재 가장 강한 공통 실패 후보다. 다만 이번 버전에서는 규칙을 수정하지 않고 관찰 결과만 기록한다.

| 공통 패턴 | CASE-01 | CASE-02 | CASE-03 | 현재 판정 |
|---|---:|---:|---:|---|
| 한 줄 정리/재진술의 독립 블록 재생성 | B7 | B9 | B13 | **3/3 반복 — 강한 수정 후보** |
| 학습코너 범위 초과 | B9/B10 | 없음 | 없음 | 1/3 — 관찰 유지 |
| 개념-예시 과분할 | B1/B2 | 용량·카드 기준 분할로 설명 가능 | B1/B2, B9/B10 일부 가능 | 불명확 — 관찰 유지 |
| Visual candidate loss | 없음 | 없음 | 없음 | 공통 문제 아님 |
| Schema issue | 없음 | 없음 | 없음 | 안정 |

## 수정 승인 기준

1. 단일 케이스 실패만으로 규칙을 추가하지 않는다.
2. 최소 2개 이상의 독립 케이스에서 같은 실패가 반복되거나 실제 운영상 치명적일 때만 수정 후보로 올린다.
3. 수정은 한 번에 하나의 개념만 최소한으로 바꾼다.
4. CASE-02처럼 현재 잘 작동하는 보호 케이스를 반드시 재실행한다.
5. 기존 성공 판단이 악화되면 즉시 rollback한다.

이번 감사 결과에서 규칙 변경을 검토할 수 있는 가장 강한 후보는 단 하나다.

> **본문의 `한 줄 정리`처럼 직전 내용을 재진술하는 문장은 새로운 독립 학습 블록을 만들지 않는다.**

하지만 이 문장조차 이번 버전에서는 엔진에 반영하지 않는다. 다음 단계에서 동일 노트를 2회 재실행하고, 다른 교과목의 유사한 recap 표현에서도 재현되는지 확인한 뒤 최소 수정 여부를 결정한다.
