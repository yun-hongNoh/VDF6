# CASE-02 Source→Block Mapping — SCAMPER 실전

## 관찰 결과

CASE-02는 현재 VDF 6.0의 **보호 케이스**로 볼 가치가 높다. 사물 변형이 많은 강의에서 image/shape를 구분하고, 카드 용량과 분류 경계를 고려한 분할이 대체로 합리적으로 작동한다.

| 원문 구조 | 생성 블록 | 판정 | 메모 |
|---|---|---|---|
| 클립 S·C·A·M·P·E·R 한 소단원 | B1 S·C·A / B2 M·P·E·R | 정상 분할로 해석 가능 | 카드 A 의미 단위 상한과 visual density 때문에 3+4 분할이 합리적 |
| 스마트폰 S와 C | B3 S / B4 C | 정상 분할로 해석 가능 | S는 대체 관계, C는 결합 4종. 과거 field test의 분류 경계 소실 문제를 피함 |
| 기타 A·M·P·E·R | B5 A·M / B6 P / B7 E / B8 R | 관찰 유지 | 서로 다른 visual gate 결과를 보존하기 위한 분리로 설명 가능. 단일 규칙 변경 근거로 쓰지 않음 |
| `한 줄 정리` | B9 사례가 보여주는 스캠퍼의 의미 | **요약·중복 재생성** | 직전 본문 전체를 다시 정의 block으로 승격 |
| `[학습코너] 실무 성찰` | 없음 | 정상 제외 | CASE-01과 달리 잘 제외됨 |
| `[AI 실전]` | 없음 | 정상 제외 | CASE-01과 달리 잘 제외됨 |
| 평가하기 | 없음 | 정상 제외 | 안정 |
| 학습정리 | 없음 | 정상 제외 | 안정 |

## 이미지 판단

- image: B1, B2, B3, B4, B6, B8
- shape: B5, B7, B9

특히 B5/A·M과 B7/E를 shape로 남긴 이유가 구체적 사물의 존재 여부가 아니라 **학습 포인트가 화면에서 실제로 남는가**를 기준으로 설명되어 있어 VDF 6.0 철학과 잘 맞는다.

## 보호 기준

향후 어떤 규칙을 수정하더라도 다음은 유지되어야 한다.

- 클립 same-form 변형 이미지 판단
- replacement_type / scale_is_the_point / branded_category 속성
- 분류 경계 보존
- 애매한 A·M/E의 shape 판정
