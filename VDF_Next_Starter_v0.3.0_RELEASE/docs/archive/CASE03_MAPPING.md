# CASE-03 Source→Block Mapping — 창의적 공학 설계

## 관찰 결과

CASE-03은 정의·목록·분류·절차 중심 강의다. 13개 block / 0 image라는 숫자만으로 과도한 shape화라고 보기는 어렵다. 실제 내용의 정체가 대부분 구조 정보이기 때문이다.

| 원문 구조 | 생성 블록 | 판정 | 메모 |
|---|---|---|---|
| 공학설계 정의 | B1 | 정상 분리 | 정의 shape |
| `더 쉽게 말하면` — 예산·시간·기술 | B2 현실적 제약 | **설명 과분할 후보** | 새 핵심 개념이라기보다 정의의 쉬운 설명일 수 있음. 관찰 유지 |
| 공학설계 주요 특징 | B3 | 정상 분리 | 목록 |
| 공학설계의 구분 4차원 | B4~B7 | 정상/관찰 | 각 분류 축이 독립적이어서 분할 가능. 하나로 합칠지 아직 open judgment |
| 다양한 문제 해결 프로세스 | B8 | 정상 분리 | 비교·대조 |
| 창의적 공학설계의 차별점 | B9 | 정상 분리 | 비교·대조 |
| 자율주행차 실무 예시 | B10 | **예시 독립 후보** | expected에서도 독립 block 여부가 open judgment. 현재 shape 판단 자체는 타당 |
| 창의적 공학설계 5단계 | B11 | 정상 분리 | 순서·절차 |
| 단계별 주요 도구 | B12 | 정상 분리 | 단계와 도구를 다른 info type으로 분리한 것은 합리적 |
| `한 줄 정리` | B13 창의적 공학설계의 전체 흐름 | **요약·중복 재생성** | B11을 사실상 다시 생성 |

## 핵심 관찰

- 자율주행차를 image로 만들지 않은 것은 오류가 아니다. 학습 정보의 정체가 차량 자체가 아니라 `문제 인식 → 아이디어 → 설계` 절차이기 때문이다.
- 가장 분명한 중복은 B11과 B13이다. B13은 원문의 `한 줄 정리`를 독립 block으로 재생성한 결과다.
