# VDF 6.0 Common Failure Patterns — Source→Block Audit

## 1. 강한 공통 패턴: inline recap 재생성

세 케이스 모두 본문 안의 `한 줄 정리`가 새로운 독립 block으로 재생성되었다.

- CASE-01C: B7 `공학적 창의성`
- CASE-02: B9 `사례가 보여주는 스캠퍼의 의미`
- CASE-03: B13 `창의적 공학설계의 전체 흐름`

빈도: **3/3 독립 케이스**

이 패턴은 현재 수정 후보로 올릴 수 있을 정도로 반복되었다. 다만 6.0의 최소 규칙 철학을 지키기 위해 이번 감사에서는 엔진을 수정하지 않는다.

향후 최소 수정 후보 문장:

> 직전 본문을 재진술하는 `한 줄 정리`·요약 문장은 새로운 독립 block을 만들지 않는다.

라벨명을 고정하지 않고 **재진술 역할**을 기준으로 해석해야 한다.

## 2. 약한 패턴: 학습코너 범위 초과

- CASE-01C: 실무 성찰과 AI 실전이 B9/B10으로 승격됨
- CASE-02: 두 코너 모두 제외됨
- CASE-03: 두 코너 모두 제외됨

빈도: **1/3**

따라서 현재 단계에서는 scope 규칙을 추가할 근거가 부족하다. 특정 코너명을 exclude 목록에 추가하지 않는다.

## 3. 관찰 패턴: 설명·예시의 독립 block 승격

- CASE-01C: 공학의 본질의 캡슐 커피 예시가 B2로 독립
- CASE-03: `더 쉽게 말하면`의 예산·시간·기술이 B2로 독립
- CASE-03: 자율주행차 실무 예시가 B10으로 독립
- CASE-02: 여러 분할이 있으나 card cap, 분류 경계, 서로 다른 visual gate로 설명 가능

현재는 **공통 실패로 확정하지 않는다**. 어떤 예시는 독립 visual block으로 가치가 있고, 어떤 설명은 핵심 내용을 별도로 전달할 수 있기 때문이다.

## 4. 공통 문제가 아닌 것

- Visual candidate loss: CASE-01/02에서 충분히 image가 생성됨
- 과도한 image 생성: 관찰되지 않음
- Schema issue: 3개 모두 계약 형태 안정
- 무조건적인 사물 이미지화: CASE-03 자율주행차에서 올바르게 억제됨

## 5. 다음 검증

1. 6.0을 변경하지 않은 상태에서 CASE-01/02/03을 각각 한 번 더 실행한다.
2. inline recap 재생성이 다시 반복되는지 확인한다.
3. 다른 교과목의 유사한 재진술 문구에서도 같은 현상이 나오면 최소 수정 후보를 승인한다.
4. 수정 시 CASE-02 전체를 보호 회귀로 사용한다.
