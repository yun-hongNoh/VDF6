# VDF 6.0

대학 온라인 강의 슬라이드의 본문 시각화를 판정하는 규칙과 도구.

## 파일

| 파일 | 무엇 | 누가 읽는가 |
| --- | --- | --- |
| `rules.json` | **규칙 원본.** 판정 기준, 카드 프롬프트, 검증 이력, 미해결 질문 | 사람 (그리고 여기서 나머지가 파생) |
| `VDF6_규칙.md` | Custom GPT 지식 파일 | GPT |
| `VDF6_지시문.md` | Custom GPT 지시문 | GPT |
| `index.html` | 블록 계획 검사기 | 브라우저 |
| `구조.html` | 동작 구조 — 처리 흐름 · 판정 트리 · 개념 관계 | 브라우저 |

`rules.json`이 원본이다. 규칙을 고칠 때는 여기를 먼저 고치고 나머지를 다시 뽑는다. 반대로 하면 셋이 갈라진다.

## 쓰는 순서

1. Custom GPT에 강의노트를 붙여넣는다
2. 답변의 `2부 — JSON`을 복사한다
3. 검사기에 붙여넣거나 파일로 끌어다 놓는다
4. 경고를 확인하고 필요하면 카드를 바꾼다
5. 프롬프트를 복사해 제미나이 앱에서 이미지를 만든다
6. 이미지와 슬롯 텍스트를 PowerPoint에 얹는다

이미지 생성은 자동화하지 않는다. 편차가 있어 사람이 골라야 하고, 검증된 표면(제미나이 앱)을 바꾸면 카드 검증이 무효가 된다.

## 현재 상태

- 검증된 카드: A · B · C · F
- 미검증: D (사례 부족) · E (후편집 전제)
- 텍스트 판단: ChatGPT Custom GPT
- 이미지 생성: 제미나이 앱

## 규칙을 고칠 때

같은 노트를 **두 번** 돌린다. 한 번 잘 나온 것은 모델이 우연히 옳게 읽은 것일 수 있다. 실제로 동일 입력에서 판정이 정반대로 갈린 적이 있다.

새 규칙은 실패가 관측될 때만 추가한다. 다듬지 않는다.

# GitHub Pages 배포

## 처음 한 번

1. GitHub에서 새 저장소를 만든다. 이름은 `vdf6` 정도. **Public**으로 한다 (Pages를 무료로 쓰려면 공개여야 한다)
2. `vdf6_검사기.html`의 이름을 **`index.html`로 바꿔서** 업로드한다. `vdf6_구조.html`은 **`구조.html`로** 바꿔 올린다. 두 페이지가 서로 링크로 연결돼 있어 이름이 다르면 끊어진다. 나머지 파일도 같이 올린다
3. 저장소의 **Settings → Pages**로 간다
4. Source를 **Deploy from a branch**, 브랜치를 **main**, 폴더를 **/ (root)**로 두고 Save
5. 1~2분 뒤 `https://<계정명>.github.io/vdf6/` 로 열린다

## 고칠 때

`index.html` 파일만 새것으로 교체하면 된다. 주소는 바뀌지 않는다.

웹에서 파일을 클릭 → 연필 아이콘 → 내용 전체 교체 → Commit. 또는 파일을 지우고 새로 업로드해도 된다.

## 주의

- 저장소가 공개면 `rules.json`도 공개된다. 강의 내용이 아니라 판정 규칙만 들어 있으니 문제는 없지만, 알고 두는 것이 낫다
- Custom GPT 주소는 검사기 화면에서 등록하면 브라우저에만 저장된다. 저장소에는 올라가지 않는다
